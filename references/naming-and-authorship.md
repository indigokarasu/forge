Never leave author blank on skills you create in this session. Never set a real name on auto-generated skills.

## Auto-Generated Skills (author: autogenerated)

When the Hermes system auto-creates a skill (hermes update, etc.):

1. Always set `metadata.author: autogenerated` — even if the skill's SKILL.md body doesn't have an author field, add one in metadata.
2. On deletion: use `skill_manage(action='delete', absorbed_into='')` — auto-generated wrapper skills are thin with no content worth merging.

## Naming Rules

### The `ocas-*` Prefix (RESERVED)

- **NEVER** create a new skill with the `ocas-*` prefix without **explicit user authorization**.
- **NEVER** rename an existing skill to `ocas-*` without **explicit user authorization**.
- The prefix is reserved for the OCAS skill system. Applying it to non-OCAS skills misrepresents their origin.

### The `util-*` Prefix

- The `util-*` prefix is for utility skills that follow the established pattern.
- **NEVER** rename an existing skill to `util-*` just to match a pattern. Only use `util-*` when the user explicitly asks.

### General Naming

- Lowercase, hyphens, max 64 chars.
- Names must be at the **class level** — not a specific PR number, error string, feature codename, or session artifact.
- If the proposed name only makes sense for today's task, it's wrong — absorb into an existing umbrella instead.

## Skill Merge Pattern

When merging a narrow skill into a class-level umbrella:

1. Move unique content into the parent's `references/` or `scripts/` directory
2. Reframe the merged content into the parent's existing section structure
3. **Do NOT** wrap merged content in `## Integrated: <name>` sections
4. Update the parent's support file map
5. Delete the now-empty narrow skill
